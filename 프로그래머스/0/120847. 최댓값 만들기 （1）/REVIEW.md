# 코드 리뷰 — 120847. 최댓값 만들기 (1)

**유형**: 정렬 / 그리디
**핵심 패턴**: 정렬 후 상위 값 선택
**체감 난이도**: 쉬움
**복습 필요도**: 중

## 1. 접근 방식
배열을 내림차순 정렬해 가장 큰 두 값을 곱한다.

## 2. 정확성 분석
이 문제의 제약(원소가 모두 0 이상)에서는 정확합니다.

## 3. 복잡도 분석
O(n log n) / O(1)~O(n)(정렬 구현에 따라).

## 4. 개선 제안
**주의**: 이 접근은 배열에 음수가 섞여 있으면 틀립니다. 예를 들어 `[-10, -9, 1, 2]`처럼 절댓값이 큰 음수 두 개의 곱이 더 클 수 있는 경우(`(-10)*(-9)=90 > 1*2=2`), 단순히 내림차순 정렬 후 상위 두 값을 곱하면 오답이 됩니다. 이번 문제는 원소가 0 이상이라는 제약 덕분에 통과했지만, 프로그래머스에는 음수를 포함하는 변형 문제(예: 최댓값 만들기 (2))가 따로 있습니다. 그 변형에서는 '가장 큰 두 값의 곱'과 '가장 작은 두 값(가장 음수인 값들)의 곱' 중 더 큰 쪽을 선택해야 합니다.

## 5. 코드 스타일
명확합니다.

## 6. 내가 막힌 지점 (추정)
코드 자체에는 막힘이 없었을 것으로 보이나, 이 정렬 기반 접근이 '원소가 음수일 수도 있다'는 조건에서는 통하지 않는다는 걸 아직 검증해보지 않은 상태로 보입니다.

## 7. 재풀이 기준
목표 시간 5분. 음수가 포함된 변형 버전을 만나면, 정렬 후 (가장 큰 두 값의 곱) vs (가장 작은 두 값의 곱) 중 최댓값을 고르는 방식으로 재작성 연습.
